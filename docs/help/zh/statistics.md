# 如何看统计

**Interception counters（拦截计数）**按 UID/应用及钩子显示已安装钩子处理的调用。
点击应用可查看分项。普通网络 API 调用也会命中钩子；计数并不能证明应用有意检测 VPN。

## 观察测试期间的活动

1. 点 **Start capture**，保存计数器基线。
2. 切换到目标应用并复现行为。
3. 返回并点 **Stop**，保留当前显示的差值以供查看。

采集时，VPN Hide 定期读取累计计数，并显示相对基线的增长。这**不是逐次调用追踪**，
不会记录每次调用的准确时间、顺序或参数；其他应用也可能出现在列表中。

停止后的结果在当前应用进程中保留，直到清除或重新采集；强制停止或重启后不会持久保存。
需要发送日志报告时，请使用[调试录制](collect-report.md)。

## 后端差异与缺失数据

- 内核和 Java 计数随对应运行组件累计，重启会清零；后端重置也可能重设采集基线。
- **Zygisk：**没有原生计数；LSPosed 仍提供 Java 和 Apps 计数。
- **KPM：**当前组件分页读取原生计数。遇到旧版或截断回复时，会隐藏不完整的原生总数，
  而不是将它当作完整结果。请按屏幕提示检查组件版本。
- 空白或不可用的结果不证明应用没有检查；还可能是读取错误、计数不受支持，或应用使用
  了已安装钩子以外的检测路径。

计数反映活动，不证明完整保护。[自检](what-the-check-proves.md)只测量其覆盖的向量；
目标应用的实际行为仍需在该应用中验证。
