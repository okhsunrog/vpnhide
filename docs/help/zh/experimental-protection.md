# 实验性保护（文件系统路径）

**Settings → Experimental protection → Hide VPN filesystem paths** 会开启一组
额外挂钩，用于隐藏 VPN 接口的文件系统条目——诸如 `/sys/class/net/<iface>` 和
`/proc/sys/net/{ipv4,ipv6}/{conf,neigh}/<iface>` 之类的路径。

## 你几乎肯定不需要它

它**默认关闭**，标准的 Native 保护通常已经足够。目前没有已知的真实应用依赖这个
检测向量。仅当你专门测试文件系统路径检测时才开启。

它有实实在在的代价：在内核后端上，这些是**全局 VFS 挂钩**，可能拖慢所有人的
文件系统操作——正因如此它才是可选的、且需要重启。

## 前提与行为

- 需要一个活动的 **kmod、KPM 或 Zygisk** 后端。
- 在 **kmod / KPM** 上，它在内核里全局拦截这些路径（约束更强），**重启后**生效。
- 在 **Zygisk** 上，它是选定应用内部的尽力而为 libc 过滤——原始系统调用和路径
  别名可能绕过它——在你**重启选定应用**后生效。

仪表盘和该设置会显示更改是已应用、等待重启，还是等待应用重启。

## 它不覆盖的检测面

如果诊断把某个面标为*“未覆盖”*（Not covered），文件系统路径正是此设置能关闭的
之一。其余的可能需要一个内核级后端（在你的设备支持时）——见
[检测向量与覆盖](detection-vectors.md)。
