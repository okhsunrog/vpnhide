# 安装 Zygisk 模块

Zygisk 通过目标进程内的 libc 钩子提供原生隐藏。完整 Core ZIP 中只包含一对 ABI
payload。按[Core 安装步骤](first-install.md)操作，无需单独的 VPN Hide Zygisk ZIP。

## 需要知道的

**优先使用兼容的内核后端。** Zygisk 钩子运行在应用进程内；银行、反欺诈及其他受保护应用
可能检测到提供程序或注入代码并拒绝运行。Zygisk 是覆盖较少的后备方案，不是推荐的起点。
内核后端也不保证不可检测，更不会隐藏已安装的 Zygisk 提供程序或 root。
直接系统调用可以绕过 libc 钩子。

Java/LSPosed 覆盖独立的一层。请查看 Core 记录的范围与缺失证据。

## 要求

需要兼容的 Zygisk 提供程序。提供程序发现 payload、Core 授权及应用实际安装钩子是不同
事实。仅有 LSPosed 并不能证明 VPN Hide payload 已就绪。

## 步骤

1. 安装配套的 APK 和通用 Core ZIP。
2. 配置所需提供程序和 Java 层作用域。
3. 安装或 Core 的切换状态要求重启时，重启并解锁设备。
4. 选择目标角色并点击**保存**。

等待重启或尚未验证的后端不代表保护已启用。按仪表盘提示操作，求助时保留诊断错误。

## 更改如何生效

已经运行的应用可能仍使用旧的钩子策略。修改配置后，强行停止并重新打开目标应用。
提供程序发现目录的变更可能需要设备重启；仅重启应用不能保证重新发现。Core 负责投递
和当前启动的授权，无需手动编辑目标文件。新诊断进程的结果不能证明所有旧游戏进程
都已更新。

在设置 → 原生后端（高级）中选择 Zygisk，并在保存前阅读及确认注入风险警告。必须已具备兼容的提供程序。Core 会准备受管理的运行模块，并说明何时需要重启设备。准备、提供程序发现、当前启动授权、实际代码使用及钩子健康状态是不同事实；待重启或未验证结果不代表保护。Auto 不会静默启用 Zygisk。旧版独立安装可能需要单独的迁移流程；Core 拒绝未验证的切换时，请保留旧安装。

升级已使用 Zygisk 的旧 Core 时，安装器仅根据精确确认的 Core 策略和运行记录保留
原选择。它准备配套的受管理 payload，不修改当前运行策略；仍需真正重启并验证新代码。
未使用的旧 payload 不会自动启用。无法证明延续性时，请保留旧安装并遵循拒绝提示。
后续更新已受管理的 Zygisk 时，请使用 Core 的配套更新流程；为保留现有运行模块，
不同版本的手动 Core-only ZIP 会被拒绝。
