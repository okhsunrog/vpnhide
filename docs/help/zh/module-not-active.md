# 模块已安装但未生效

仪表盘会显示每个模块的状态。「已安装但未生效」几乎总是几种具体原因之一——屏幕上的
消息会指明是哪一种。

## 常见原因

- **缺少 KernelPatch 运行时。** “内核未修补”表示 VPN Hide 未检测到可用的 KPM 运行时。安装 `vpnhide-kpm.zip` 不会提供它。请参阅 [KPatch-Next-Module 下载及运行时安装步骤](kpm-install.md)。
- **缺少 VPN Hide Core。** 所有后端都由核心模块（`vpnhide-core.zip`）加载。没有它就什么都不会
  加载，应用启动时会显示 **“VPN Hide Core 未运行”**。从同一版本安装它并重启。
- **重启以激活。** 刚安装的原生模块要重启后才加载：核心每次启动只选择并加载一次后端。请重启设备。
- **缺少 LSPosed 作用域。** Java 层需要在 VPN Hide 的作用域里加入**系统框架**。在
  LSPosed / Vector 中加上并重启。
- **多于一个原生后端。** 只有在唯一时核心才会加载后端：装了两个（或在内置 VPN Hide 的内核上
  又装了一个）时，它**一个也不加载**，仪表盘会列出它们。卸载多余的并重启。
- **KPM 没有 SuperKey。** APatch/FolkPatch 无法用受信任令牌加载 KPM。在**设置 → 安全**
  里保存你的 SuperKey，核心随后无需重启即可加载等待中的 KPM。
- **已废弃的 1.x 模块。** 仍安装着 1.x 的 **VPN Hide (Ports)** 或 **VPN Hide (Built-in kernel)**
  模块。2.0 中二者都已被核心模块取代，其旧的开机脚本会干扰核心：卸载它并重启。
- **安装损坏。** 缺少有效载荷（`.ko`、`.kpm` 或 Zygisk 库）表示 ZIP 没装好。通过 root 管理器的模块页面重新
  安装最新发布的完整 ZIP——不要解压里面的单个文件。
- **内核不受支持。** KPM 对这个内核家族没有经过验证的偏移表。改用 Zygisk 后端。

无论消息怎么写，都按它指出的动作去做，然后点**刷新**（或在提示时重启）。如果仍不能
激活，请收集一份[调试报告](collect-report.md)。
