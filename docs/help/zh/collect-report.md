# 收集调试报告

**设置 → 调试（Debugging）→ Debug export** 会生成一个文件（`vpnhide_debug_*.zip`），
里面是诊断所需的信息，能看到你的设备实际做了什么——比纯文字描述有用得多。

## 怎么做

1. 复现问题：在 VPN 开启的情况下，冷启动目标应用，让它的检查重新运行。
2. 打开**设置 → 调试（Debugging）→ Debug export**。
3. 选择要包含什么。**详细日志**（dmesg、logcat、探测）通常就是 bug 报告需要的。已安装
   应用列表和内核镜像默认关闭——只有在开发者要求时才加上。
4. 点 **Export**，把 ZIP 发到 Telegram 群或 GitHub issue。

如果需要跨越冷启动的连续日志，先在**设置 → Developer** 里打开 **Debug logging**，复现，
再导出。Debug export 里的采集会自行开启日志，所以通常不需要手动开——之后记得关回去。

## 里面有什么、没有什么

调试包包含诊断报告、模块状态和你选择的日志——诊断隐藏所需的技术状态，不是用来收集
个人数据的。除非你启用，已安装应用列表不会被包含。在没有 VPN、或 VPN Hide 没走这条
VPN 时采集的记录是不完整的；应用会提示你。
