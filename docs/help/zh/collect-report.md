# 收集调试报告

打开 **设置 → Debugging**。配置或模块问题可用状态快照；在另一个应用中出现的问题
应使用录制来捕获。

## 快照：查看当前状态

1. 查看已保存的诊断结果；只有需要新的一次检查时才点击**重试**。
2. 打开 **Debug export**，为诊断报告保留 **Verbose logs** 开启。
3. 除非被要求，否则不要启用已安装应用列表或内核镜像。
4. 导出，然后保存或分享 ZIP。

导出读取 Core 已保存的证据，包括未完成的检查和基础设施错误。它与 VPN 和分流设置无关。

## 录制：复现另一个应用的问题

1. 在 **设置 → Debugging** 中先点 **Start recording**。
2. 切换到目标应用，必要时强制停止并重新打开，然后复现问题。
3. 返回 VPN Hide，停止录制，再保存或分享文件。
4. 描述预期行为、实际行为、目标应用及版本、故障的大致时间，以及它是否走 VPN 隧道。

调试导出只为自身采集临时开启日志，并保存现有诊断证据。它无法补回目标应用出错时未启用的
详细日志。它还会在采集采集窗口前清空内核日志缓冲区；事后的快照不能替代故障录制。

需要在采集之外持续记录时，可先开启 **设置 → 开发者 → Debug logging**，复现后
再关闭。采集结束会恢复采集前的日志开关状态。

## 选择要分享的内容

无需通读整个 `state.json`。请在导出对话框中选择压缩包内容：除非开发者要求，
否则不要启用完整已安装应用列表或内核镜像。诊断报告应保留详细日志；录制应在
复现问题前开始，并在复现结束后停止。

报告包含配置、模块状态和诊断结果。详细采集还会添加日志及网络、系统信息。
不包含完整应用列表，并不会移除已配置的包名或日志中的所有应用和网络信息。

通过应用内的联系方式约定支持渠道，将压缩包交给开发者，而不是公开发布。
这能限制接收者范围，但不会让报告变成匿名文件。反馈问题时请附上诊断报告：
其中的日志和状态快照是排查原因所需的信息。
