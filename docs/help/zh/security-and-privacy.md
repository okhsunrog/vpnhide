# 安全与隐私

VPN Hide 为选定应用过滤受支持的本地 VPN 信号。它不提供匿名性，不隐藏 root，
也不保证应用或其服务器允许访问。

## 需要信任的组件

你需要信任 Android 系统、内核、root 管理器、挂钩框架及安装的模块。VPN Hide
针对普通应用的检测，不防御恶意 root 程序或已被攻破的系统。
隐藏 VPN 信号也不保证 VPN Hide 本身或其钩子无法被检测。

## 隐藏不等于验证路由

诊断通过只代表 VPN Hide 进程中已执行的检查结果，不证明另一个应用完全检测不到
VPN，也不证明它的连接一直经过隧道。Java 钩子可能返回物理网络；显式绑定到该网络，
在 Android 和 VPN 策略允许绕过时可能获得直连。

如果必须走隧道，请保留相应的 VPN 阻断策略，并验证目标应用的连接。
在另一个应用里检查 IP 不能验证目标应用的路由。见
[直连还是走隧道](split-tunneling.md#场景-2应用必须走-vpn但不能看到-vpn)和
[自检检查什么](what-the-check-proves.md)。

## 钩子状态与诊断结果

钩子数量表示哪些挂钩已安装。详细诊断进一步执行真实的检测探测并检查结果。
支持 root 对照的检查会确认 root 能看到某个信号，而应用看不到。
隐藏成功的结果证明受测检测方式在你的设备上已被防护，而不只是模块加载成功。

请以详细结果区分有效隐藏、已检测到的泄漏、SELinux 阻断探测以及无法测量。
探测以 VPN Hide 的身份运行；另一个应用可能使用不同的角色设置或 API。
见[自检检查什么](what-the-check-proves.md)和[检查结果含义](check-result-meanings.md)。
隐藏失败时，VPN Hide 不会阻断所有流量。

## 保存的密钥

在 APatch/FolkPatch 上保存 SuperKey，会将它持久存储到
`/data/adb/vpnhide/superkey`，归 root 所有，权限为 `0600`。应用或设备重启后仍保留。
应用提供保存和清除，没有仅用于当前会话的模式。Root 可以读取该文件。
密钥不存储在导出的配置 JSON 中。如果受信任的 `su` 令牌可用，就不需要保存密钥。
见 [SuperKey 存储](kpm-install.md#superkey-存储)。

## 开发者访问与报告

Agent Control 是可选功能，默认关闭。其本地 HTTP 接口需要访问令牌，并能控制配置。
令牌保存在应用私有文件中，也会写入日志供电脑工具使用。获得令牌并能连接接口的人
就能控制应用；localhost 不能识别特定应用。端口转发可能让手机之外的客户端连接，
但仍需令牌。仅在需要的工具会话中开启，用完后关闭。

报告可能包含配置、网络信息和日志。无需通读整个 JSON：在导出对话框中选择要包含的
内容。除非被要求，否则不要启用完整应用列表或内核镜像。通过约定的支持渠道将压缩包
交给开发者，而不是公开发布。即使不包含完整应用列表，报告仍可能保留已配置的包名
和日志中的信息。见[收集调试报告](collect-report.md)。
