# 更改何时生效

在「**隐藏**」选择角色后，点击**保存**并等待结果。然后在 Android 设置中强制停止
目标应用，再重新打开：即使隐藏已应用，它仍可能缓存旧的 VPN 检测结果。

## 已保存不一定等于已应用

- **成功：**配置已保存，所请求的应用步骤已完成。
- **已保存，但应用失败：**选择已写入，但部分层可能仍使用旧配置。阅读错误，解决原因
  （如 root 权限或模块缺失），再使用界面提供的重新应用操作。
- **结果未知 / 更改暂停：**VPN Hide 无法确认上一次操作的结果。点击 **Check again**。
  不要用反复导入或切换设置来绕过它。如果复查仍无效，请[收集报告](collect-report.md)。
- **未保存的编辑：**选择列表中的改动在保存成功前只是草稿。**Discard edits** 恢复已保存
  的选择。若提示冲突，先查看更新后的配置，再重新进行所需更改。

## 重启应用还是手机？

| 更改 | 操作 |
|---|---|
| Java / Apps 角色、内核 Native 的目标和钩子 | 保存成功；强制停止目标应用以清除其缓存 |
| Zygisk 的目标或钩子 | 保存，再强制停止并重新打开目标应用；钩子在进程启动时安装 |
| Ports 的目标或端口范围 | 保存成功；防火墙规则无需重启即可更改 |
| 安装、更新、启用或移除模块 | 重启手机以完成 root 管理器的操作 |
| 安装或更新 VPN Hide APK，修改 LSPosed 作用域或启用状态 | 重启手机；已加载到 `system_server` 的钩子会一直运行到重启 |
| 内核后端的实验性文件系统保护 | 重启手机，并按待处理状态提示操作 |
| Zygisk 的实验性文件系统保护 | 重启选定应用 |

技术上，保存是运行激活器来传递配置，而不是卸载并重启内核后端。激活器把已保存的配置转换成各后端实际读取的形式：内核后端立即接收；Zygisk 模块在目标应用进程每次启动时读取自己的 `targets.txt` 文件；Ports 规则会重新应用。这些运行时文件在每次开机以及 VPN Hide 每次冷启动时也会重新生成，因此不会与已保存的配置长期不一致。文件中按 UID 而非包名列出应用：如果重新安装了目标应用，它可能获得新的 UID，所以在强制停止它之前请再保存一次（重启手机或冷启动 VPN Hide 效果相同）。

## 仪表盘刷新

返回应用时，VPN Hide 会刷新状态。如果仪表盘仍显示此前的 VPN 状态，请点 **Retry**
发起新检查。只重启目标应用不会刷新或证明它的隐藏效果；见
[自检检查什么](what-the-check-proves.md)。
