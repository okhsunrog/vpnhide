# 设置隐藏

隐藏要配置在你想**对其**隐藏 VPN 的那个应用上——银行、政务、电商。VPN 应用本身
在这里不需要配置：它是被隐藏的一方。

> 例如：要让银行应用看不到 VPN，就把下面的角色配置在**银行**上。你的 VPN 客户端
> （比如 WireGuard）另行处理——在隐藏 VPN 应用的名单里。

## 常见情况

### 应用检测到了 VPN

给这个应用 **Java** 和 **Native** 角色。Java 负责 Android 通过 Java API 暴露给应用
的 VPN 信号；Native 负责应用通过内核或 libc 能看到的部分。大多数检测器都会被其中
之一拦下，所以两个都开最稳妥。

### 应用在查找已安装的 VPN 客户端

有些应用并不探测连接——它们扫描已安装的软件包列表，一旦发现已知的 VPN 就拒绝运行。
给正在扫描的那个应用打开 **Apps** 角色，并确认你的 VPN 客户端在隐藏名单里
（**设置 → 隐藏 VPN 应用**，或[立即打开](vpnhide://hidden-apps)）。大多数 VPN 客户端
VPN Hide 会自动识别；你也可以手动隐藏。

### 应用在检查本地端口

少数应用会查找监听在本地回环（localhost）上的 VPN 或代理守护进程。**Ports** 角色
让这些端口在该应用看来是关闭的。默认会隐藏所有本地回环端口；可在应用的单项设置里
限定到指定范围。

### 你在用游戏加速器

游戏加速器（UU、迅游、腾讯等）本身就是一个 VPN：在 Android 上它会建立一个 VpnService
隧道，把你选定的游戏导入其中。于是系统会看到一个活动的 VPN 和一个已安装的 VPN 应用，
其他应用可能因此有所反应。如果在加速器开启时，银行或其他应用「因为有 VPN」而拒绝运行，
就用 **Java + Native** 把 VPN 对*那个*应用隐藏，并把加速器加入隐藏 VPN 应用名单，让软件包
扫描发现不了它。由于加速器只代理你选定的游戏，你要隐藏的那个应用本来就不在隧道里。

这里说的是把加速器的 VPN 对*其他*应用隐藏。把它对你正在加速的那款游戏隐藏、以绕过该游戏
自身的检查，是另一回事，VPN Hide 无法保证。

加速器通常只代理固定的游戏列表，而不是任意应用，所以往往无法把 VPN Hide 加入它的隧道。
这也是为什么加速器开启时，「概览」里的自检可能提示无法运行——这是正常现象，并非失败。
请以目标应用是否正常来判断隐藏效果。

### 更改什么时候生效？

点击**保存**之后：Java、内核级后端和端口规则会立即生效。只有 Zygisk 钩子需要把目标
应用强制停止并重新打开，因为它们要加载进该应用的进程。无论哪种情况，已经探测过的
应用可能仍缓存着旧结果——请在再次检查前重启它。

### 都设置好了，VPN 却仍被检测到

打开[诊断](vpnhide://diagnostics)并运行检查。它们检验的是 VPN Hide 自身的隐藏，而不是
那个应用的具体行为：通过就说明各隐藏层在工作——但应用仍可能因自身原因拒绝（服务器端
检测、你尚未覆盖的已安装应用扫描、缓存的结果）。下一步见 **解决问题**。

## 四个角色

配置在你要隐藏的对象应用上：

- **Java** —— 隐藏通过 Android Java API 暴露的 VPN 信号（NetworkCapabilities、
  NetworkInfo、LinkProperties）。
- **Native** —— 隐藏通过内核或 libc 能看到的 VPN 信号，包括网络接口列表。VPN Hide
  只保存一份 Native 选择，且只有当前生效的后端会起作用。
- **Apps** —— 给应用一份净化过的已安装软件包视图，使其看不到你标记为隐藏的 VPN
  客户端。
- **Ports** —— 让本地回环上的 VPN/代理端口在该应用看来是关闭的。

对于 Java、Native 和 Ports，可以点按角色旁的设置图标，为该应用单独选择钩子或端口
范围。**\*** 表示该应用有自定义的单项钩子设置。

准备好了？[打开「隐藏」标签页](vpnhide://hiding)并选择要配置的应用。
