# Какой Native-бэкенд выбрать

Native скрывает признаки VPN ниже Java framework: в libc, прямых системных
вызовах, netlink и `/proc/net`. Установите приложение и **полный
`vpnhide-core.zip` из одной сборки**. Core содержит payload бэкендов и
автоматически выбирает совместимую реализацию.

**Предпочтителен совместимый ядерный бэкенд.** Хуки Zygisk работают внутри
процессов приложений. Банковские, антифрод- и другие защищённые приложения могут
обнаружить провайдер или внедрённый код и отказаться работать. Zygisk — запасной
вариант с меньшим покрытием, а не рекомендуемая отправная точка. Ядерный бэкенд
не гарантирует незаметность и не скрывает установленный провайдер Zygisk или root.
Прямые системные вызовы могут обходить libc-хуки.

## Варианты

- **Built-in:** совместимый драйвер VPN Hide уже встроен в ядро. Установка Core
  не добавляет его в обычное ядро.
- **Kmod:** Core выбирает подходящий `.ko` из комплекта по данным ядра.
  См. [модуль ядра](kmod-install.md).
- **KPM:** бэкенд из комплекта, которому нужна работающая аутентифицированная
  среда KernelPatch. См. [требования KPM](kpm-install.md).
- **Zygisk:** userspace-вариант из комплекта, которому нужен совместимый
  провайдер Zygisk. Прямые syscalls могут обходить libc-хуки.
  См. [требования Zygisk](zygisk-install.md).

Java/LSPosed и Native закрывают разные пути. Роли Apps нужен Java/LSPosed,
а Ports входит в Core. См. [Векторы обнаружения](detection-vectors.md).

## Оставьте один Native-бэкенд

Core обеспечивает взаимоисключение работающих нативных бэкендов. Все варианты
в универсальном Core ZIP поставляются вместе; их наличие не является конфликтом.
Старым отдельным модулям и независимо загруженным бэкендам может потребоваться
миграция. Сохраните конфигурацию и рабочую установку до подготовки и проверки
замены. Следуйте восстановлению Core и не загружайте kernel payload вручную.

## Пусть выбирает Дашборд

Выбор делает Core. Дашборд показывает выбор, применение и сохранённые результаты
диагностики. Неизвестная совместимость и неполное покрытие остаются видимыми.
Наличие бэкенда не доказывает работу защиты. См.
[Модуль установлен, но не активен](module-not-active.md).

## Расширенный выбор kernel-бэкенда

В настройках «Нативный бэкенд» можно сохранить Авто или явный выбор kernel-семейства
для следующей загрузки устройства. Core сначала проверяет совместимость и все
настроенные правила. Это не перезагружает устройство и не меняет работающий
бэкенд. Ожидание перезагрузки и неподтверждённое применение — отдельные состояния,
они не доказывают здоровье защиты. Авто выбирает совместимый Built-in, затем Kmod,
и не пробует KPM или Zygisk автоматически после отказа. Новый выбор Zygisk и
управляемая публикация ещё реализуются; этот диалог их не включает.
