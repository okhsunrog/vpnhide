# Способы обнаружения и покрытие

У приложений есть несколько способов заметить VPN. Каждый закрывается ролью или
бэкендом VPN Hide. Это пользовательская сводка; полная матрица по каждому бэкенду
— в документации для разработчиков в репозитории.

| Что может проверить приложение | Чем закрывается |
|---|---|
| `NetworkCapabilities`, `NetworkInfo`, `LinkProperties` (Java-API) | Java (LSPosed) |
| Список сетевых интерфейсов (`getifaddrs` / `NetworkInterface`) | Native (ядро / libc) |
| Правила маршрутизации и netlink-дампы | Native |
| Сокет, привязанный к интерфейсу туннеля | Native |
| Установленные VPN-приложения (скан пакетов) | Apps |
| Localhost-порты VPN / прокси | Ports |

## Примечания

- **Java vs Native.** Часть сигналов доходит до приложения и через Java-API, и
  через вызовы libc/ядра. Java закрывает первое, нативный бэкенд — второе;
  надёжнее включить оба.
- **Прямые raw syscalls.** Приложение, вызывающее ядро напрямую (`svc #0`) в обход
  libc, закрывается только **kernel-бэкендом** (kmod / встроенный / KPM), а не
  libc-хуками Zygisk.
- **SELinux.** На некоторых прошивках вектор уже заблокирован политикой SELinux —
  скрыт, но не силами VPN Hide, поэтому зависит от устройства.
