# Скрыть localhost-порты (Ports)

Некоторые VPN/прокси-клиенты слушают локальные порты, например `127.0.0.1:7890`.
Приложение может прощупывать их даже при скрытом VPN-интерфейсе. **Ports** блокирует
такие подключения для приложения-цели, не останавливая сам прокси.

## Настройка

Ports входит в модуль **VPN Hide Core** (`vpnhide-core.zip`), который уже есть в
любой установке; ставить ничего дополнительно не нужно. Оставшийся от 1.x модуль
**VPN Hide (Ports)** нужно удалить — пока он установлен, Дашборд показывает ошибку.

1. На вкладке **Скрытие** включите **Ports** у приложения, которое проверяет порты.
2. Если нужны конкретные диапазоны, задайте их значком настройки рядом с Ports, затем **Сохраните**.
3. Дождитесь успешного применения и заново откройте приложение-цель.

Изменение ролей или диапазонов применяет правила при сохранении без
перезагрузки; кроме того, core заново применяет их при каждой загрузке. При ошибке см. [Сохранение и применение](saving-applying.md).

## Покрытие и побочные эффекты

По умолчанию блокируются все TCP/UDP-порты IPv4 loopback `127.0.0.0/8` и IPv6 `::1`
для выбранного UID. TCP получает reset, UDP — ответ «порт недоступен». Другие UID
не затрагиваются; пакеты с общим UID разделяют и блокировку.

Любое приложение может использовать локальный сервис для обычной работы. Блокировка
всех портов способна сломать такие функции, включая инструменты браузера и локальные
интеграции. В этом случае отключите Ports для приложения или сузьте правила до портов
прокси, которые нужно скрыть. Это не закрывает все способы обнаружения локальных
сервисов, например Unix-сокеты или доступ к сервису по другому сетевому адресу.

## Отключение

Для одного приложения снимите роль Ports и успешно сохраните. Правила живут в
файрволе ядра до перезагрузки: удаление модуля core лишь не даёт ему применить их
снова, а уже загруженные правила очищает только перезагрузка.
