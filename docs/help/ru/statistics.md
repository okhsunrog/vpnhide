# Как читать статистику

Раздел **Interception counters** (счётчики перехватов) показывает, как часто
выбранные вами приложения реально попадали в установленный хук — это события
времени выполнения, о которых сообщают активные бэкенды, посчитанные
**нарастающим итогом с момента загрузки**. Это окно в то, что прощупывают ваши
приложения-цели, а не табло очков.

## Что вы видите

- **Счётчики пусты**, пока выбранное приложение не вызовет хук. «Пока нет
  статистики» просто значит, что ничего из выбранного не прощупывало с момента
  загрузки.
- **Apps probing VPN** перечисляет приложения, попавшие в хуки; нажмите на любое,
  чтобы увидеть полную разбивку по хукам (какими способами оно проверяло).

## Сессия захвата — наблюдать за одним приложением в реальном времени

Чтобы увидеть, какие именно проверки VPN делает конкретное приложение:

1. Нажмите **Start capture**.
2. Переключитесь в приложение, которое хотите проверить, и попользуйтесь им.
3. Каждая его проверка VPN появляется в списке по мере поступления.

Нажмите **Stop**, когда закончите; результаты сохранятся, пока вы не начнёте новый
захват или не очистите их. Это самый быстрый способ понять, *как* именно
конкретное приложение ищет VPN.

## Различия по бэкендам

- **Zygisk** — нативные счётчики недоступны. Счётчики Java и Apps всё равно
  сообщает LSPosed.
- **KPM** — у него больше счётчиков, чем канал управления может вернуть за раз,
  поэтому частичные нативные итоги скрыты; счётчики Java и Apps показываются.

## Что из этого не следует

Большое число не значит, что приложение «более подозрительное», а **ноль** не
доказывает, что приложение никогда не проверяет — оно может использовать способ
обнаружения, который этот бэкенд не закрывает, или закешировало прежний
результат. Счётчики показывают активность на установленных хуках; это не
доказательство полного скрытия. Для этого используйте самопроверку — см.
[Что проверяет самопроверка](what-the-check-proves.md).
