# Как читать статистику

**Счётчики перехватов / Interception counters** показывают вызовы, обработанные
установленными хуками, с разбивкой по UID/приложению и хуку. Нажмите на приложение
для подробностей. Обычный вызов сетевого API тоже попадает в хук: счётчик не доказывает,
что приложение намеренно пыталось обнаружить VPN.

## Наблюдение во время проверки

1. Нажмите **Start capture**, чтобы зафиксировать начальные значения счётчиков.
2. Переключитесь в приложение-цель и воспроизведите нужное поведение.
3. Вернитесь и нажмите **Stop**, чтобы оставить показанные изменения для просмотра.

Во время захвата VPN Hide периодически читает накопительные счётчики и показывает
прирост относительно начала. Это **не трассировка отдельных вызовов**: точное время,
порядок и аргументы каждого вызова здесь не записываются. В списке могут появляться
и другие приложения.

Остановленный результат остаётся в текущем процессе до очистки или нового захвата;
это не долговременная запись после принудительной остановки или перезагрузки.
Для логов к баг-репорту используйте [запись отладки](collect-report.md).

## Различия бэкендов и отсутствие данных

- Ядерные и Java-счётчики накапливаются, пока работает соответствующий компонент.
  Перезагрузка сбрасывает их; сброс бэкенда также может начать отсчёт захвата заново.
- **Zygisk:** нативных счётчиков нет; Java и Apps по-прежнему сообщает LSPosed.
- **KPM:** текущие компоненты читают нативные счётчики постранично. При старом или
  усечённом ответе неполные итоги не выдаются за полные. Следуйте сообщению на экране
  и проверьте версии компонентов.
- Пустой результат или недоступные данные не доказывают отсутствие проверок. Учитывайте
  ошибки чтения, неподдерживаемые счётчики и способы обнаружения вне установленных хуков.

Счётчики измеряют активность, а не полноту защиты. [Самопроверка](what-the-check-proves.md)
измеряет свои векторы; поведение конкретного приложения проверяйте в самом приложении.
