# Установка бэкенда KPM

KPM — это Native-бэкенд уровня ядра для тех ядер, которые загружаемый `.ko`
**не потянет**: старые или не-GKI ядра (например, 4.9, 4.14), вендорские ядра
без исходников, ядра, отклоняющие неподписанные модули. Он скрывает на уровне
ядра так же, как `.ko`, без внедрения libc-хуков в процесс цели. Это не гарантирует
невидимость для любых проверок целостности или root. Это **один
универсальный модуль** — подбирать GKI-версию не нужно. Сначала прочитайте
[Какой Native-бэкенд выбрать](choosing-native.md).

## Нужна среда KernelPatch

KPM использует inline-хуки ядра, для которых в ядре должна присутствовать среда
KernelPatch. Выберите путь под свой root:

- **APatch / FolkPatch** — KernelPatch уже встроен. Установите ZIP модуля.
  Сохранённый **SuperKey** нужен, только если активация по доверенному токену
  недоступна: [Хранение SuperKey](#хранение-superkey).
- **Magisk / KernelSU / KernelSU-Next** — используйте [**KPatch-Next-Module**](https://github.com/KernelSU-Next/KPatch-Next-Module/releases/latest) и
  шаги установки ниже либо интегрируйте KPatch-Next при самостоятельной
  сборке. Одна установка VPN Hide эту среду не предоставляет.

Если среды нет, Дашборд напишет, что *«ядро не пропатчено средой KernelPatch»*.

## Шаги

1. Убедитесь, что среда KernelPatch присутствует (см. выше).
2. Скачайте `vpnhide-kpm.zip` (Дашборд назовёт файл).
3. Установите **весь ZIP** через экран **Modules** своего root-менеджера как
   APM/Magisk-совместимый модуль. **Не** распаковывайте и не загружайте
   внутренний файл `vpnhide.kpm` сам по себе — без обвязки у него нет активатора,
   загрузочных скриптов и доставки конфигурации, и скрытие не заработает.
4. На APatch / FolkPatch сохраняйте **SuperKey**, только если приложение просит
   ключ: [Хранение SuperKey](#хранение-superkey).
5. **Перезагрузитесь** и откройте **Дашборд** — Native-бэкенд должен показывать
   **Active**.

## Хранение SuperKey

Сохраняйте SuperKey, если APatch/FolkPatch не может активировать KPM по
доверенному токену `su` и обзор просит ключ. В **Настройки → Безопасность**
введите ключ, заданный в APatch/FolkPatch. Сохранение записывает его в файл,
доступный только root, между перезапусками приложения и телефона, а не только
на текущую сессию. Очистка удаляет сохранённую копию. При следующей активации
ключ может снова понадобиться, если доступ по доверенному токену недоступен.
См. [Безопасность и приватность](security-and-privacy.md#сохранённые-ключи).

## Поддерживаемые ядра

KPM проверяет семейство вашего ядра при загрузке. Поддерживаются 4.4, 4.9, 4.14,
4.19, 5.4, 5.10, 5.15, 6.1, 6.6 и 6.12. Остальные семейства отклоняются, а не
угадываются. Если Дашборд пишет *«ядро не поддерживается… нет проверенной
таблицы смещений»*, используйте [бэкенд Zygisk](zygisk-install.md).

## Почему на некоторых ядрах показывается 10 хуков

При выключенном скрытии файловых путей полная установка KPM показывает
**OK · hooks: 10** на ядрах до 5.3 и **OK · hooks: 11** начиная с 5.3.
На старых ядрах для привязки сокета к интерфейсу уже требуется право, которого
нет у обычных приложений, поэтому KPM не устанавливает там хук привязки сокета.

Счётчик учитывает установленные логические идентификаторы и группы хуков,
а не физические точки перехвата. Если включить **Скрывать пути VPN в файловой
системе** и после перезагрузки группа успешно установится, она добавит единицу:
получится **11** и **12** соответственно. Одна группа может использовать несколько
точек перехвата. Число проверок в диагностике считается отдельно — см.
[Что проверяет самотест](what-the-check-proves.md).

## Если установлен, но неактивен

Дашборд называет причину:

- **Нужен SuperKey** — APatch/FolkPatch не смог загрузить модуль по доверенному
  токену `su`. Сохраните SuperKey в **Settings → Security** и перезагрузитесь
  (или нажмите Refresh). Переустановка ZIP не помогает.
- **Нужна среда** — в ядре нет среды KernelPatch; установите её (см. выше).
- **Обнаружена standalone-установка** — загружен голый `vpnhide.kpm`, а модуля
  ZIP нет. Удалите отдельную запись, установите полный `vpnhide-kpm.zip` с экрана
  Modules и перезагрузитесь.
- **Конфликт с модулем ядра** — установлены и `.ko`, и KPM; они хукают одни и те
  же функции и могут намертво повесить устройство, поэтому KPM отступает.
  Удалите один из них. **Никогда не держите оба активными.**

При ошибке загрузки используйте **Settings → Debugging → Collect debug log**,
чтобы приложить вывод со старта к отчёту — см.
[Собрать отчёт для диагностики](collect-report.md).

## Где скачать и как установить KPatch-Next-Module

Для Magisk / KernelSU / KernelSU-Next:

1. Скачайте [KPatch-Next-Module.zip](https://github.com/KernelSU-Next/KPatch-Next-Module/releases/latest/download/KPatch-Next-Module.zip)
   из [официальных релизов](https://github.com/KernelSU-Next/KPatch-Next-Module/releases/latest).
   Это среда для KPM, а не сам `vpnhide-kpm.zip`; нужны оба модуля.
2. Установите ZIP через **Модули** root-менеджера, затем откройте WebUI
   модуля KPatch-Next. Если менеджер не открывает WebUI, действие модуля
   предложит [KsuWebUIStandalone](https://github.com/KOWX712/KsuWebUIStandalone/releases).
3. В WebUI откройте **Patch** и пропатчите загрузочный образ. Чтобы среда
   появилась в работающем ядре, изменённый образ нужно прошить, затем
   перезагрузиться. Одна установка ZIP этого не заменяет.
   Перед прошивкой сохраните рабочий загрузочный образ и способ его восстановления.
4. После перезагрузки проверьте статус **Working** в WebUI. Затем установите
   `vpnhide-kpm.zip` по шагам выше; если он уже установлен, откройте VPN Hide
   и обновите состояние.

На APatch / FolkPatch отдельно ставить KPatch-Next-Module обычно не требуется:
среда входит в пропатченное ими ядро. Если VPN Hide всё же сообщает, что среды
нет, проверьте её состояние в root-менеджере и соберите
[отчёт для диагностики](collect-report.md). Одного скриншота недостаточно,
чтобы отличить отсутствие среды от ошибки её обнаружения.

Если патчинг недоступен или не подходит вашему устройству, используйте
[Zygisk](zygisk-install.md) вместо KPM. Для собственной сборки ядра есть
[проект KPatch-Next](https://github.com/KernelSU-Next/KPatch-Next).
