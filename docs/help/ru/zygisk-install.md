# Установка модуля Zygisk

Zygisk скрывает признаки VPN через libc-хуки внутри целевых процессов. Обе ABI
входят одной парой в полный Core ZIP. Используйте [установку Core](first-install.md);
отдельный ZIP VPN Hide Zygisk не нужен.

## Чего ожидать

**Предпочтителен совместимый ядерный бэкенд.** Хуки Zygisk работают внутри
процессов приложений. Банковские, антифрод- и другие защищённые приложения могут
обнаружить провайдер или внедрённый код и отказаться работать. Zygisk — запасной
вариант с меньшим покрытием, а не рекомендуемая отправная точка. Ядерный бэкенд
не гарантирует незаметность и не скрывает установленный провайдер Zygisk или root.
Прямые системные вызовы могут обходить libc-хуки.

Java/LSPosed покрывает отдельный слой. Учитывайте показанный Core охват
и недостающие доказательства.

## Требования

Нужен совместимый провайдер Zygisk. Обнаружение payload, авторизация и реально
установленные хуки — отдельные факты. Само наличие LSPosed не доказывает
готовность payload VPN Hide.

## Шаги

1. Установите согласованные APK и универсальный Core ZIP.
2. Настройте необходимый провайдер и scope Java-слоя.
3. Перезагрузитесь, когда этого требует установка или состояние перехода Core,
   затем разблокируйте устройство.
4. Выберите роли целей и нажмите **Сохранить**.

Ожидание перезапуска или отсутствие подтверждения не означают активную защиту.
Следуйте указанию Дашборда и сохраняйте ошибки диагностики для обращения за помощью.

## Как применяются изменения

Уже запущенные приложения могут сохранить старую политику хуков. После изменения
конфигурации принудительно остановите и заново откройте цель. Изменение discovery
провайдера может требовать перезагрузки; перезапуск приложения сам по себе
обнаружение не гарантирует. Core владеет доставкой и авторизацией текущего boot;
файлы целей вручную не редактируются. Новый диагностический worker не доказывает,
что все старые процессы игр обновились.

В Настройки → Нативный backend (расширенные) выберите Zygisk, прочитайте и подтвердите предупреждение о внедрении перед сохранением. Совместимый provider уже должен быть доступен. Core подготовит управляемый runtime и сообщит о необходимости перезагрузки. Подготовка, обнаружение provider, разрешение текущей загрузки, фактическое использование кода и исправность перехватов — разные факты; ожидающий или непроверенный результат не является защитой. Auto не включает Zygisk скрытно. Для старых отдельных установок может требоваться изолированная миграция; сохраняйте их, если Core отклоняет непроверенный переход.

При обновлении старого Core с уже работающим Zygisk установщик сохраняет этот
выбор только по точно подтверждённым записям политики и runtime Core. Он готовит
соответствующий управляемый payload, не меняя текущую политику; нужны настоящая
перезагрузка и проверка нового кода. Неиспользуемый старый payload не включается.
Если continuity не подтверждается, сохраните старую установку и следуйте сообщению
об отказе. Для последующих обновлений управляемого Zygisk используйте парный
updater Core: другой ручной ZIP только с Core отклоняется ради сохранения runtime.
